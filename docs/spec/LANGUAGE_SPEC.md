# RealScript 语言规范

> Phase 3B 已实现的最小 `class`、`new`、字段访问、对象 null 与身份相等边界见 [OBJECT_MODEL_V0.md](OBJECT_MODEL_V0.md)。构造函数、方法、继承与接口仍属于后续实现。


- 规范版本：Draft v0.1
- `language_version`：0.1
- 状态：规范草案，不保证源代码向后兼容

## 1. 范围

RealScript 是一门面向游戏引擎嵌入、静态强类型、具有 C# 表达习惯的独立语言。

本规范定义源程序的词法、名称绑定、类型检查和可观察运行语义。实现可以采用字节码解释、C++17 AOT 或 JIT，但所有后端必须产生一致结果。

RealScript v0.1 不兼容 C#、CLR、CTS、IL 或 .NET 程序集。语法相似不表示语义兼容。

## 2. 源文本与词法

### 2.1 编码

源文件必须使用 UTF-8。实现必须接受可选 UTF-8 BOM，但不得在语义中保留 BOM。

换行可以是 LF 或 CRLF。编译器应当把二者映射为统一源码行号。

v0.1 的标识符限制为 ASCII：

```ebnf
identifier-start = "A"…"Z" | "a"…"z" | "_" ;
identifier-part  = identifier-start | "0"…"9" ;
identifier       = identifier-start, { identifier-part } ;
```

字符串和注释可以包含完整 Unicode。未来语言版本可以扩展 Unicode 标识符，但不得改变 v0.1 ASCII 标识符的含义。

### 2.2 注释

```csharp
// 单行注释

/* 块注释 */
```

块注释允许嵌套。注释不参与语义，但编译器和格式化工具应保留文档注释：

```csharp
/// Adds damage to an entity.
```

### 2.3 关键字

v0.1 保留以下关键字：

```text
module import as public internal private protected
class struct interface enum delegate sealed abstract
virtual override static readonly const new this base
void bool byte sbyte short ushort int uint long ulong
float double char string object
if else switch case default for foreach while do
break continue return throw try catch finally
in ref out params var null true false
generic where is as typeof sizeof
async await yield checked unchecked
```

其中 `generic` 为保留字，v0.1 泛型声明使用尖括号语法，不要求使用该关键字。

### 2.4 字面量

实现必须支持：

- 十进制、十六进制和二进制整数；
- `f` 后缀的 `float`；
- 无后缀的 `double`；
- 字符和字符串；
- `true`、`false`、`null`。

```csharp
42
0xff
0b1010_0110
1.5f
3.1415926
'R'
"RealScript"
```

数字分隔符 `_` 只能出现在数字之间，不能连续出现或出现在前缀、后缀旁边。

普通字符串支持 `\n`、`\r`、`\t`、`\\`、`\"`、`\0`、`\uXXXX` 和 `\UXXXXXXXX`。无效 Unicode 标量值必须产生编译错误。

## 3. 编译单元和模块

每个源文件属于且只属于一个模块。模块声明必须是文件中第一个非注释声明：

```csharp
module Game.Defense;
```

导入声明位于模块声明之后、其他声明之前：

```csharp
import Engine.Math;
import Engine.ECS as ECS;
```

模块名由点分隔的标识符组成。模块是以下内容的边界：

- 名称可见性；
- 增量编译；
- 能力授权；
- AOT 编译单元；
- 热重载和状态迁移；
- 元数据版本和 Schema 兼容。

同一模块可以由多个源文件组成。模块内顶层声明的顺序不影响名称可见性，但静态初始化顺序必须由依赖图确定，不得依赖文件系统枚举顺序。

循环模块依赖是无效程序。实现必须报告至少一条完整依赖环路径。

## 4. 声明和可见性

### 4.1 顶层声明

v0.1 顶层允许：

- `class`；
- `struct`；
- `interface`；
- `enum`；
- `delegate`；
- 模块级函数；
- `const`；
- 属性标注声明所需的类型。

不允许可变模块级字段。持久全局状态必须通过显式服务、资源或模块状态对象表达，以便热重载、存档和确定性检查。

### 4.2 访问级别

- `public`：对导入该模块的代码可见；
- `internal`：仅模块内可见；
- `private`：仅声明类型内可见；
- `protected`：声明类型及派生类型可见。

顶层声明默认 `internal`。类型成员默认 `private`。接口成员隐式 `public`，不得声明更窄访问级别。

### 4.3 名称解析

名称解析顺序必须是：

1. 当前局部作用域；
2. 参数和类型参数；
3. 当前类型成员；
4. 当前模块顶层声明；
5. 显式导入别名；
6. 非别名导入的公开成员。

多个导入提供同名候选时，使用未限定名称是编译错误，程序必须使用限定名或导入别名。

## 5. 类型系统

### 5.1 内建类型

```text
bool
byte, sbyte
short, ushort
int, uint
long, ulong
float, double
char
string
object
void
```

整数类型使用二进制补码表示。整数位宽固定：8、16、32、64 位。`char` 表示一个 Unicode 标量值，而不是 UTF-16 code unit。

`float` 符合 IEEE 754 binary32，`double` 符合 binary64。除确定性档位另有约束外，允许平台使用硬件浮点，但不得改变 NaN、无穷和有符号零的语言级比较规则。

### 5.2 类型分类

类型分为：

- 值类型：整数、浮点、`bool`、`char`、`enum`、`struct`；
- 引用类型：`class`、`interface`、`delegate`、`string`、数组；
- 特殊类型：`void`、类型参数、可空值类型。

### 5.3 默认值

- 数值：零；
- `bool`：`false`；
- `char`：U+0000；
- 枚举：底层整数零，即使没有具名成员；
- 结构体：每个字段的默认值；
- 可空值类型：无值；
- 引用类型：`null`，但不可空引用局部变量必须通过明确赋值检查后才能读取。

对象字段总是获得默认初始化。局部变量在明确赋值前不得读取。

## 6. 数值语义

### 6.1 整数运算

整数加、减、乘、取负和显式数值转换具有 checked/unchecked 两种语义：

- `checked`：超出目标类型范围时抛出 `OverflowException`；
- `unchecked`：结果按目标位宽进行二进制截断。

v0.1 默认上下文为 `unchecked`。项目或模块可以通过编译选项要求默认 `checked`，但该选项必须写入模块元数据，且字节码和 AOT 必须保持一致。

整数除零必须抛出 `DivideByZeroException`。有符号最小值除以 `-1` 在 checked 上下文抛出 `OverflowException`，在 unchecked 上下文返回截断后的最小值。

移位计数先转换为 `int`，再与位宽减一进行按位与：32 位类型使用 `count & 31`，64 位类型使用 `count & 63`。

### 6.2 浮点运算

浮点除零遵循 IEEE 754，不抛出整数除零异常。`NaN` 与任何值（包括自身）的 `==` 比较为 false，`!=` 为 true。

实现不得在未声明的 Fast Math 模式中重新结合表达式、忽略 NaN 或折叠有符号零。Fast Math 必须是显式属性或构建档位，并且不得用于 Deterministic Profile。

### 6.3 求值顺序

表达式操作数从左到右求值。函数实参按源码顺序从左到右求值。赋值表达式先计算目标位置，再计算右值，最后写入。

后端优化不得改变可观察异常、原生调用、分配、调试序列点或写入顺序。

## 7. 转换

### 7.1 隐式转换

允许：

- 较窄无符号整数到能够完整表示其范围的较宽类型；
- 较窄有符号整数到更宽有符号类型；
- `float` 到 `double`；
- 派生类引用到基类或已实现接口；
- 非空引用到对应可空引用；
- `null` 到可空引用或可空值类型；
- `T` 到 `T?`。

隐式转换不得丢失整数精度或改变符号。

### 7.2 显式转换

显式转换可以缩窄整数、改变有符号性、将浮点转换为整数、向下转换引用或拆箱。

浮点到整数：

- NaN 或无穷在 checked 上下文抛出 `OverflowException`；
- 超出范围在 checked 上下文抛出；
- unchecked 行为仍必须由 Runtime Intrinsic 明确定义，不得直接依赖 C++ cast 的未定义或实现定义行为。

### 7.3 用户定义转换

v0.1 不支持用户定义隐式或显式转换运算符。该限制减少重载解析复杂度并提高可读性。

## 8. 结构体、类和接口

### 8.1 `struct`

结构体是值类型：

- 赋值复制完整值；
- 默认不可继承其他结构体或类；
- 可以实现接口；
- 可以包含引用字段，GC 必须通过类型描述图追踪；
- 不允许直接或间接形成无限递归内联布局；
- 不允许用户定义无参构造函数；
- 不允许终结器。

`readonly struct` 的实例字段必须为只读，实例方法中的 `this` 按 `in` 语义处理。

### 8.2 `class`

类是 GC 管理的引用类型：

- 最多继承一个基类；
- 可以实现多个接口；
- 方法默认非虚；
- 虚分派必须显式使用 `virtual`、`abstract` 和 `override`；
- `sealed` 类禁止继承；
- `sealed override` 禁止继续重写；
- 不允许用户定义终结器。

构造过程必须先完成基类构造，再执行实例字段初始化和当前构造函数体。构造期间不得把未完成对象发布到其他线程或长期宿主存储。

### 8.3 `interface`

接口只包含契约：

- 不含实例字段；
- v0.1 不含默认实现；
- v0.1 不含静态抽象成员；
- 接口继承可以多继承，但必须形成无环图；
- 类或结构体必须提供每个成员的唯一实现。

相同签名从多个接口继承时可以由一个实现满足。返回类型仅协变的重载不构成不同签名。

### 8.4 枚举

枚举必须声明或推导固定底层整数类型。v0.1 默认底层类型为 `int`。

枚举不隐式转换为整数。位标志枚举必须标注 `[Flags]`，但该属性不改变底层位运算语义，只影响诊断、格式化和编辑器显示。

## 9. 成员、属性和索引

字段保存状态。属性由 `get` 和可选 `set` 访问器组成：

```csharp
float Health
{
    get => current;
    private set => current = value;
}
```

属性访问在语义上是方法调用，不保证无副作用。编译器可以内联，但不得改变可观察行为。

自动属性由编译器生成不可直接命名的后备字段。热重载和序列化使用稳定字段 ID，而不是后备字段显示名称。

v0.1 可以支持单参数索引器：

```csharp
Item this[int index] { get; set; }
```

## 10. 函数和参数

函数签名由名称、类型参数数量、参数类型及参数传递模式组成。返回类型不参与重载区分。

参数模式：

- 按值：调用方值被复制；
- `in`：只读借用，函数不得写入；
- `ref`：读写借用，调用前必须已赋值；
- `out`：写出借用，函数返回前必须在全部正常路径赋值；
- `params`：仅允许最后一个参数，调用端可以提供数组或展开参数。

`ref`、`in` 和 `out` 引用不得：

- 存入对象字段；
- 被普通 Lambda 捕获；
- 跨越 `await` 或 `yield`；
- 返回局部变量地址；
- 超过其来源存储位置生命周期。

重载解析按以下优先级选择唯一最佳候选：

1. 精确类型和参数模式匹配；
2. 标准隐式转换；
3. 泛型类型推断后的标准隐式转换；
4. `params` 展开。

无法得到唯一最佳候选是编译错误。

## 11. 泛型

```csharp
struct Optional<T>
{
    bool hasValue;
    T value;
}
```

支持约束：

```csharp
T Find<T>(Entity entity) where T : struct, IComponent;
```

v0.1 约束类别：

- `class`；
- `struct`；
- 基类；
- 一个或多个接口；
- `new()`，表示可由规范默认构造规则创建。

值类型实例必须单态化。引用类型实例可以共享代码，但共享实现必须保持与单态化实现相同的异常、装箱和反射行为。

不支持在运行时构造编译期未知的封闭泛型类型。

## 12. 可空性

引用类型默认不可空：

```csharp
Actor actor;   // 不可空
Actor? target; // 可空
```

编译器必须执行流敏感空值分析。成功的 `null` 检查、模式检查和抛出路径可以收窄类型。

空值抑制运算符 `!` 可以关闭当前表达式的静态警告，但不得移除运行时空值检查。

值类型 `T?` 表示 `Optional<T>` 等价语义，不要求与标准库具体布局相同。

引擎句柄失效不等于语言 `null`。例如非空 `Entity` 仍可能包含已经失效的代际句柄，必须使用 `IsValid` 检查。

## 13. 表达式

v0.1 支持：

- 字面量和名称；
- 成员、属性和索引访问；
- 函数和委托调用；
- 一元、二元和条件运算；
- 赋值与复合赋值；
- 对象、结构体和数组创建；
- `is` 模式和安全 `as` 转换；
- `typeof(T)`；
- Lambda；
- `await`；
- 空值合并 `??` 和空值条件访问 `?.`。

`&&`、`||` 和 `??` 必须短路求值。

复合赋值 `x op= y` 必须只求值一次 `x` 的存储位置。

引用相等与值相等必须区分。类默认 `==` 比较引用身份，除非语言未来引入明确运算符重载；字符串 `==` 比较内容。

v0.1 不支持用户定义运算符重载。

## 14. 语句和控制流

支持：

- 块；
- 局部变量声明；
- 表达式语句；
- `if`；
- `switch`；
- `while`、`do`、`for`、`foreach`；
- `break`、`continue`；
- `return`；
- `throw`；
- `try`、`catch`、`finally`；
- `checked`、`unchecked` 块。

所有非 `void` 函数必须在每条可达正常路径返回值或抛出异常。

`switch` 不允许隐式贯穿。多个标签可以共享一个语句块。编译器应当对枚举和封闭类型的非穷尽匹配发出诊断。

`foreach` 的具体协议由标准库接口定义，但循环变量的求值顺序和释放行为必须在 HIR 降级时显式化。

## 15. 异常

只有继承自标准 `Exception` 的类实例可以被抛出。

异常按动态类型匹配最先出现的兼容 `catch`。`finally` 在正常退出、`return`、`break`、`continue` 和异常展开时执行。

v0.1 不支持异常过滤器。AOT 后端不得让脚本异常穿越未声明为异常安全的 C++ 帧。脚本异常必须通过 Runtime ABI 展开或转换为受控错误结果。

资源释放应优先使用标准库的确定性作用域模式；不允许用户终结器承担资源管理。

## 16. 委托和 Lambda

委托是类型化函数引用。实例方法委托包含目标对象和函数身份。

Lambda 只有捕获外部变量时才需要闭包对象。按值捕获复制值；引用类型变量按引用值复制。`ref`、`in`、`out` 局部不得被可逃逸 Lambda 捕获。

编译器必须执行逃逸分析以判断闭包能否栈上分配，但该优化不得改变对象身份可观察性。

## 17. `async`、任务和协程

`async` 函数必须返回标准任务类型，例如 `GameTask` 或 `GameTask<T>`。

`await`：

1. 先从左到右求值等待对象；
2. 若已完成，继续同步执行；
3. 若未完成，保存状态机并把控制权返回调度器；
4. 恢复时从同一逻辑执行上下文继续。

`ref` 类局部、栈借用和未固定宿主指针不得跨越 `await`。

Deterministic Profile 中只允许等待 Tick、确定性事件、确定性任务依赖或明确许可的同步点。不得等待墙上时间或操作系统调度结果。

v0.1 不规定通用多线程 `async`。默认任务调度器是宿主驱动的游戏线程调度器。

## 18. 属性和能力

属性为声明附加编译期或元数据语义：

```csharp
[Component]
[Serializable]
[StableId("...")]
[Deterministic]
```

属性构造参数必须是编译期常量、类型引用或其数组。属性不得在编译期间执行任意用户代码。

模块能力由清单授予，例如：

```text
engine.ecs.read
engine.ecs.write
engine.audio.play
filesystem.assets.read
network.client
```

调用需要未授权能力的原生 API 是编译错误；外部字节码加载时仍必须再次验证。

## 19. 确定性模块

`[Deterministic]` 模块必须满足：

- 不读取墙上时间；
- 不使用系统随机源；
- 不直接创建线程或依赖任务竞态；
- 不依赖未规定顺序的容器迭代；
- 不调用未标记为确定性的宿主函数；
- 不启用 Fast Math；
- 不使用平台相关字符串排序和区域设置；
- 所有外部输入必须在 Tick 边界记录并可回放。

编译器必须进行静态检查；运行时必须通过 Capability 和 API 表再次限制。

普通 `float` 的跨架构位级确定性不是默认保证。权威模拟应使用未来的固定点类型、受控浮点档位或由宿主明确认证的平台集合。

## 20. 诊断要求

编译器必须为无效程序至少提供：

- 稳定诊断代码；
- 主源码范围；
- 简短消息；
- 相关声明位置；
- 对常见错误的修复建议（若可靠）。

错误恢复不得让后续生成的可执行模块绕过类型安全。存在错误诊断的模块默认不得输出可加载字节码或 AOT 产物。

## 21. v0.1 明确不支持

- `dynamic`；
- 裸指针和任意 `unsafe`；
- 多类继承；
- 默认接口实现；
- 用户定义终结器；
- 用户定义运算符和转换；
- 表达式树；
- 运行时代码生成；
- 完整 LINQ 查询语法；
